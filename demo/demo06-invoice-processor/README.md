> 第 03 章模組 06。發票 Email 抵達後 **60 秒內**完成提取、分類、發布、歸檔，全程無人工資料輸入。

| 每月回收 | 8 小時（約 $640 的高階人力產能） |
| 建置費 | $350（一次性） |
| 月費 | $85 |

## 1. Before / After

| 階段 | Before（人工） | After（Agent） |
| --- | --- | --- |
| 取得發票 | 開信、下載 PDF、存到暫存資料夾 | Email 抵達即觸發（**The Eyes**） |
| 讀取資料 | 肉眼看廠商、金額、日期、稅額 | Claude 提取四欄位並自檢稅額（**The Brain**） |
| 分類 | 憑記憶挑會計科目，新人常挑錯 | 關鍵字規則對應科目，未命中進「待分類支出」 |
| 入帳 | 打開 Xero 手動逐欄輸入 | API 發布，附標準化參照號（**The Hands**） |
| 歸檔 | 各自命名，月底找不到 | `YYYY-MM-DD_<廠商>_<金額><幣別>.pdf` |
| 耗時 | 每張 15 分鐘 × 20 張／月 ≈ **5 小時**（純輸入） | 每張 **60 秒**，全自動 |
| 實際成本 | 含追催、對帳、找檔，帳務經理每月 **8 小時** | 只剩覆核少數低信心發票（約 10 分鐘） |

> **註**：5 小時是純資料輸入時間，8 小時是 Webb & Partners 實測的完整週期成本（含追催缺漏發票、
> 月底對帳找檔）。財務模型以 8 小時計。

### 架構：The Eyes / The Brain / The Hands

```
[The Eyes]              [The Brain]                        [The Hands]
Email Inbox   ──►  OpenClaw + Claude                ──►  Xero / QuickBooks API
（發票抵達）         ├─ extractor.py 提取四欄位              ├─ 建立應付帳款單
                     │   廠商 / 金額 / 日期 / 稅額           └─ 附標準化檔名參照
                     ├─ Decimal 驗稅（小計＋稅額＝總額）
                     │   隱含稅率須落在 0% / 5% / 20%
                     └─ 信心不足 ──► AMBER + needs_review
                                     （攔下，不入帳）
```

**三個環節缺一不可**：眼睛沒接上就沒有觸發，大腦沒驗算就會把錯的數字寫進帳，
手沒有 API 權限就只能產出另一份要人抄的清單。

## 2. 安全設計（為什麼這個模組敢自動入帳）

| 閘門 | 行為 |
| --- | --- |
| **信心閘門** | 缺任一必填欄位、或小計＋稅額對不上總額、或隱含稅率不在 `allowed_tax_rates`，一律 `needs_review`，**永遠不會**送進會計系統 |
| **金額精度** | 全程 `decimal.Decimal`，禁止 float。金額進出 JSON 一律字串 |
| **保守解析** | 金額必須帶兩位小數才採信。模糊掃描的 `1,240.O0`（字母 O）直接解析失敗 —— 失敗好過猜錯 |
| **自主權階梯** | 入帳是不可逆動作，唯有 `supervised_auto` ＋ 收件人在白名單才真的發布；否則只建草稿 |
| **外幣警示** | 非本位幣發票照常入帳，但發 AMBER 提醒確認匯率來源 |

## 5. Client Pitch 話術

> 「每一張發票在抵達後 60 秒內，就被處理、分類並發布到您的會計軟體中。沒有手動資料輸入。沒有遺漏的發票。」

補充三句（客戶一定會問的）：

1. **「萬一它讀錯呢？」** —— 讀不清楚它不會猜。缺欄位或稅額對不上就標記待覆核，
   由您的人 2 分鐘看一眼；它只自動處理它有把握的那 90%。
2. **「會不會把亂七八糟的東西塞進我的帳？」** —— 科目對應表在設定檔裡，您可以隨時調整；
   沒命中規則的一律進「待分類支出」，不會亂猜科目。
3. **「要多久才能上線？」** —— 一個半小時內完成，當天就開始省時間。

## 6. 使用方式

```bash
# 標準離線驗收（零憑證、零網路）
python main.py --mock

# 跑完流程但不發布也不通知
python main.py --mock --dry-run

# 降級為草稿模式（只分類、不自動入帳）
python main.py --mock --autonomy draft

# 串接真實 Claude + Xero（需環境變數）
python main.py --live --notify telegram
```

`--live` 所需環境變數（一律不寫進設定檔）：

| 變數 | 用途 |
| --- | --- |
| `ANTHROPIC_API_KEY` | Claude 提取 |
| `XERO_ACCESS_TOKEN` / `XERO_TENANT_ID` | Xero 發布 |
| `QUICKBOOKS_ACCESS_TOKEN` / `QUICKBOOKS_REALM_ID` | 改用 QuickBooks 時 |

### 測試

```bash
python -m pytest test_main.py -v
```

## 8. 已知限制

- **不解析 PDF**：`raw_text` 假設郵件閘道已把 PDF 轉成文字，模組本身零 PDF 依賴。
- **關鍵字比對是子字串**：新增規則時避免用過短的字（`aws` 會誤中 `laws`）。
- **外幣不換算**：外幣發票以原幣入帳並發 AMBER，匯率交由會計系統處理。
- **`allowed_tax_rates` 預設為英國稅制**（0% / 5% / 20%），換國家必須改設定檔。
